#커피 주문 앱

## 1. 프로젝트 개요

### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

##2. 기술 스택
- 프런트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 주문하기 화면

### 4.1 화면 목적
사용자가 커피 메뉴를 확인하고 장바구니에 담은 뒤 주문한다. 앱을 열면 이 화면이 먼저 보인다.

### 4.2 화면 구성
화면은 위에서 아래로 세 영역으로 나뉜다. 각 영역은 사각형 테두리로 구분한다.

1. 헤더
2. 메뉴 목록
3. 장바구니

### 4.3 헤더
- 왼쪽에는 앱 이름 `COFFE-APP`을 표시한다.
- 오른쪽에는 `관리자`를 표시한다. 선택하면 관리자 화면으로 이동한다.

### 4.4 메뉴 목록
메뉴를 가로로 나열한다. 메뉴 하나는 카드 하나이며, 카드 안 내용은 위에서 아래로 다음 순서다.

1. 사진 영역. 이미지가 없으면 `사진`이라고 표시한다.
2. 메뉴 이름. 온도는 이름 뒤 괄호로 붙인다.
3. 가격. 천 단위 쉼표와 `원`을 붙인다.
4. 간단 설명.

와이어프레임의 예시 메뉴는 다음과 같다.

| 메뉴 이름 | 가격 | 설명 |
| --- | --- | --- |
| 아메리카노(ICE) | 2,500원 | 간단설명 |
| 아메리카노(HOT) | 2,500원 | 간단설명 |
| 말차라떼(ICE) | 4,500원 | 간단설명 |

동작은 다음과 같다.

- 메뉴 카드를 선택하면 그 메뉴 1개가 장바구니에 담긴다.
- 이미 담긴 메뉴를 다시 선택하면 수량이 1 증가한다.
- 카드 안에 별도의 담기 버튼은 없다.
- 이 화면에서는 재고 수량을 보여 주지 않는다.

### 4.5 장바구니
장바구니는 메뉴 목록 아래에 둔다.

- 왼쪽 위에는 `장바구니`를 표시한다.
- 오른쪽 위에는 `총 금액 {금액}원`을 표시한다. 금액은 담긴 항목의 합계다.
- 목록의 한 줄은 `{메뉴 이름} X {수량}`과 그 줄의 금액이다. 줄 금액은 단가에 수량을 곱한 값이다.
- 같은 메뉴는 한 줄로 합친다.
- 오른쪽 아래에는 `주문하기` 버튼을 둔다.

와이어프레임의 예시는 다음과 같다.

- 아메리카노(ICE) X 1, 2,500원
- 말차라떼(ICE) X 1, 4,500원
- 총 금액 7,000원

동작은 다음과 같다.

- 장바구니가 비어 있으면 목록은 비어 있고 총 금액은 `0원`이다. 이때 `주문하기`는 주문을 만들지 않는다.
- `주문하기`를 선택하면 장바구니에 담긴 메뉴와 수량으로 주문을 만들고, 장바구니를 비운다.
- 주문 완료를 알리는 별도 화면은 없다. 주문 뒤에는 빈 장바구니가 있는 주문하기 화면을 유지한다.

### 4.6 표시 규칙
- 금액은 `2,500원`처럼 천 단위 쉼표와 `원`으로 표시한다.
- 수량은 `X 1`처럼 `X`와 숫자로 표시한다.
- 온도는 메뉴 이름의 일부로 표시한다. HOT와 ICE는 서로 다른 메뉴다.

### 4.7 이 화면에서 하지 않는 것
- 샷, 사이즈 같은 옵션 선택
- 장바구니 수량 감소와 항목 삭제
- 로그인, 결제
- 재고 수량 표시와 재고 수정. 재고와 주문 상태 관리는 관리자 화면의 범위다.

## 5. 관리자 화면

### 5.1 화면 목적
관리자가 주문 건수를 확인하고, 메뉴 재고를 조정하고, 주문의 제조 상태를 바꾼다. 주문하기 화면의 `관리자`를 선택하면 이 화면으로 이동한다.

### 5.2 화면 구성
화면은 위에서 아래로 네 영역으로 나뉜다. 각 영역은 사각형 테두리로 구분한다.

1. 헤더
2. 대시보드
3. 재고
4. 주문현황

### 5.3 헤더
- 왼쪽에는 앱 이름 `COFFEE-APP`을 표시한다.
- 오른쪽에는 `주문하기`를 표시한다. 선택하면 주문하기 화면으로 이동한다.

### 5.4 대시보드
영역 왼쪽 위에 `대시보드`를 표시한다. 그 아래에는 칸 네 개를 가로로 둔다. 각 칸은 이름과 건수를 보여 준다.

| 칸 | 의미 | 표시 예 |
| --- | --- | --- |
| 총 주문 | 모든 주문 수 | 0건 |
| 주문 접수 | 주문 접수 상태인 주문 수 | 0건 |
| 제조 중 | 제조 중 상태인 주문 수 | 0건 |
| 제조 완료 | 제조 완료 상태인 주문 수 | 0건 |

건수는 `0건`처럼 숫자 뒤에 `건`을 붙인다. 주문이 없거나 상태가 바뀌면 네 칸의 숫자가 바로 갱신된다. 총 주문은 주문 접수, 제조 중, 제조 완료의 합과 같다.

### 5.5 재고
영역 왼쪽 위에 `재고`를 표시한다. 메뉴 하나를 카드 하나로 가로로 나열한다. 카드 안 내용은 위에서 아래로 다음 순서다.

1. 메뉴 이름. 주문하기 화면과 같은 이름을 쓴다.
2. 재고 수량. `10개`처럼 숫자 뒤에 `개`를 붙인다.
3. `+` 버튼과 `-` 버튼.

와이어프레임의 예시 재고는 다음과 같다.

| 메뉴 이름 | 재고 |
| --- | --- |
| 아메리카노(ICE) | 10개 |
| 아메리카노(HOT) | 10개 |
| 말차라떼(ICE) | 10개 |

동작은 다음과 같다.

- `+`를 누르면 해당 메뉴 재고가 1 증가한다.
- `-`를 누르면 해당 메뉴 재고가 1 감소한다.
- 재고는 0개보다 작아지지 않는다. 0개일 때 `-`를 눌러도 수량은 0개로 유지된다.
- 재고는 이 버튼으로만 바뀐다. 주문이 들어와도 재고는 줄지 않는다.

### 5.6 주문현황
영역 왼쪽 위에 `주문현황`을 표시한다. 주문 하나는 한 줄이다. 한 줄은 왼쪽부터 주문 시각, 주문 메뉴, 금액, 상태 버튼 순이다.

- 주문 시각은 `11월 18일 15:02`처럼 `M월 D일 HH:mm`로 표시한다.
- 주문 메뉴는 `{메뉴 이름} X {수량}`이다. 한 주문에 메뉴가 여러 개면 같은 줄에 함께 보여 준다.
- 금액은 그 주문의 총액이다. 천 단위 쉼표와 `원`을 붙인다.
- 오른쪽 끝의 상태 버튼에는 현재 상태를 표시한다.

와이어프레임의 예시는 다음과 같다.

- 11월 18일 15:02, 아메리카노(ICE) X 1, 2,500원, 버튼 `접수 주문`

동작은 다음과 같다.

- 주문하기 화면에서 주문이 만들어지면 주문현황 맨 위에 한 줄이 추가된다. 처음 상태는 주문 접수이고, 버튼 문구는 `접수 주문`이다.
- 최근 주문이 위에 온다.
- 주문이 없으면 목록은 비어 있다.
- 상태 버튼을 누르면 주문이 다음 상태로 바뀌고, 버튼 문구와 대시보드 건수도 함께 바뀐다.

상태 순서는 다음과 같다.

1. 주문 접수. 버튼 문구는 `접수 주문`이다.
2. 제조 중. 버튼 문구는 `제조 중`이다.
3. 제조 완료. 버튼 문구는 `제조 완료`이다.

`제조 완료` 버튼을 눌러도 상태는 바뀌지 않는다. 완료된 주문은 목록에 그대로 남는다.

### 5.7 표시 규칙
- 대시보드 건수는 `0건`처럼 숫자와 `건`으로 표시한다.
- 재고는 `10개`처럼 숫자와 `개`로 표시한다.
- 금액과 수량은 주문하기 화면과 같다. 금액은 `2,500원`, 수량은 `X 1`이다.
- 메뉴 이름은 주문하기 화면과 같다. HOT와 ICE는 서로 다른 메뉴다.

### 5.8 이 화면에서 하지 않는 것
- 메뉴 추가, 메뉴 삭제, 가격과 설명 수정
- 주문 삭제
- 로그인, 결제
- 제조 완료 이후의 상태

## 6. 백엔드

주문하기 화면과 관리자 화면이 같은 PostgreSQL 데이터를 읽고 쓰도록 Node.js와 Express로 API를 만든다. 화면 구성은 4장, 5장을 따른다. 백엔드에서는 옵션을 저장하고, 주문이 저장될 때 메뉴 재고를 줄인다.

### 6.1 데이터 모델

메뉴, 옵션, 주문 세 가지를 저장한다. 주문 한 건은 메뉴를 여러 개 담을 수 있으므로, 주문의 내용은 주문 항목으로 나눈다. 금액과 옵션 이름은 주문 당시 값을 복사해 둔다. 나중에 메뉴 가격이나 옵션 가격이 바뀌어도 과거 주문 금액은 바뀌지 않는다.

#### 6.1.1 Menus

커피 메뉴 하나다. HOT와 ICE는 서로 다른 메뉴다.

| 필드 | 설명 | 제약 |
| --- | --- | --- |
| id | 메뉴 식별자 | 기본 키 |
| name | 커피 이름 | 필수. 예: `아메리카노(ICE)` |
| description | 설명 | 필수 |
| price | 가격 | 필수. 0 이상의 정수, 원 단위 |
| image_url | 이미지 주소 | 없으면 비운다. 화면에는 `사진`으로 표시 |
| stock | 재고 수량 | 필수. 0 이상의 정수 |

처음 데이터는 다음과 같다. 재고는 메뉴마다 10이다.

| name | price | description |
| --- | --- | --- |
| 아메리카노(ICE) | 2500 | 차갑고 깔끔한 에스프레소 |
| 아메리카노(HOT) | 2500 | 따뜻하고 진한 에스프레소 |
| 말차라떼(ICE) | 4500 | 우유를 더한 달콤한 아이스 말차 |

#### 6.1.2 Options

메뉴에 붙는 선택 항목이다. 같은 메뉴에 옵션이 여러 개일 수 있고, 옵션은 하나의 메뉴에만 연결된다.

| 필드 | 설명 | 제약 |
| --- | --- | --- |
| id | 옵션 식별자 | 기본 키 |
| menu_id | 연결할 메뉴 | 필수. Menus.id를 참조 |
| name | 옵션 이름 | 필수. 예: `샷 추가` |
| price | 옵션 가격 | 필수. 0 이상의 정수, 원 단위 |

처음 데이터는 메뉴 세 개 모두에 다음 옵션을 연결한다.

| name | price |
| --- | --- |
| 샷 추가 | 500 |
| 시럽 추가 | 500 |

#### 6.1.3 Orders

주문 한 건이다.

| 필드 | 설명 | 제약 |
| --- | --- | --- |
| id | 주문 식별자 | 기본 키 |
| ordered_at | 주문 일시 | 필수. 서버가 저장하는 시각 |
| status | 주문 상태 | 필수. `주문 접수`, `제조 중`, `완료` 중 하나 |
| total_price | 주문 금액 | 필수. 주문 항목 금액의 합 |

주문 내용은 주문 항목으로 저장한다.

| 필드 | 설명 | 제약 |
| --- | --- | --- |
| id | 주문 항목 식별자 | 기본 키 |
| order_id | 소속 주문 | 필수. Orders.id를 참조 |
| menu_id | 주문한 메뉴 | 필수. Menus.id를 참조 |
| menu_name | 주문 당시 메뉴 이름 | 필수 |
| quantity | 수량 | 필수. 1 이상의 정수 |
| options | 선택한 옵션 | 이름과 가격의 목록. 없으면 빈 목록 |
| line_price | 항목 금액 | 필수. `(메뉴 가격 + 선택 옵션 가격의 합) × 수량` |

같은 메뉴라도 선택한 옵션이 다르면 다른 주문 항목이다. 메뉴와 옵션이 같으면 한 항목으로 합치고 수량만 늘린다.

### 6.2 데이터 스키마를 위한 사용자 흐름

1. 주문하기 화면은 Menus와 그 메뉴의 Options를 가져와 메뉴 카드와 옵션을 표시한다. Menus의 재고 수량은 이 화면에 표시하지 않는다. 재고 수량은 관리자 화면의 재고 영역에만 표시한다.
2. 사용자가 메뉴 카드를 선택하면 그 메뉴와 그때 선택된 옵션이 장바구니에 표시된다. 장바구니는 브라우저에만 있고, 이 단계에서는 데이터베이스에 쓰지 않는다.
3. 장바구니에서 `주문하기`를 누르면 주문 시각, 메뉴, 수량, 옵션, 금액을 Orders에 저장한다. 새 주문의 상태는 `주문 접수`다. 저장에 성공하면 장바구니를 비운다.
4. 관리자 화면의 주문현황은 Orders를 주문 시각이 최근인 것부터 표시한다. 한 줄에는 주문 일시, 메뉴와 수량과 옵션, 금액, 상태를 보여 준다. 상태가 `주문 접수`인 주문을 누르면 `제조 중`이 되고, `제조 중`인 주문을 누르면 `완료`가 된다. `완료`는 더 바뀌지 않는다. 대시보드의 총 주문, 주문 접수, 제조 중, 제조 완료는 각각 전체 주문 수와 세 상태의 주문 수다. 제조 완료 칸은 상태가 `완료`인 주문을 센다.

재고는 주문이 저장될 때 메뉴별로 주문 수량만큼 줄어든다. 관리자 화면의 `+`, `-`로도 재고를 바꿀 수 있다. 재고는 0보다 작아지지 않는다.

### 6.3 API 설계

기본 경로는 `/api`다. 요청과 응답 본문은 JSON이다. 금액은 원 단위 정수다. 시각은 ISO 8601 문자열로 주고, 화면에서는 `M월 D일 HH:mm`으로 표시한다.

공통 오류는 다음이다.

| 상황 | HTTP 상태 |
| --- | --- |
| 본문이나 주소의 값이 잘못됨 | 400 |
| 메뉴, 옵션, 주문을 찾을 수 없음 | 404 |
| 재고가 주문 수량보다 적음 | 409 |

오류 본문은 `{ "message": "설명" }`이다.

#### 6.3.1 커피 메뉴 목록 조회

`주문하기` 화면을 열면 데이터베이스에서 커피 메뉴 목록을 불러온다.

- 메서드와 경로: `GET /api/menus`
- 요청 본문: 없음
- 응답: `200`
- 각 메뉴는 `id`, `name`, `description`, `price`, `imageUrl`, `options`를 포함한다.
- `options`의 항목은 `id`, `name`, `price`다.
- 이 응답에는 재고 수량을 넣지 않는다.

예시 응답의 메뉴 하나:

```json
{
  "id": 1,
  "name": "아메리카노(ICE)",
  "description": "차갑고 깔끔한 에스프레소",
  "price": 2500,
  "imageUrl": null,
  "options": [
    { "id": 1, "name": "샷 추가", "price": 500 },
    { "id": 2, "name": "시럽 추가", "price": 500 }
  ]
}
```

#### 6.3.2 주문 저장

사용자가 커피를 선택하고 장바구니의 `주문하기` 버튼을 누르면 주문 정보를 데이터베이스에 저장한다. 저장하면서 해당 메뉴의 재고도 주문 수량만큼 줄인다.

- 메서드와 경로: `POST /api/orders`
- 요청 본문: `items` 배열. 항목은 `menuId`, `quantity`, `optionIds`다.
- `optionIds`에 있는 옵션은 그 `menuId`에 연결된 옵션이어야 한다.
- 서버가 Menus.price와 Options.price로 `linePrice`와 `totalPrice`를 계산한다. 클라이언트가 보낸 금액은 저장하지 않는다.
- 같은 메뉴를 항목 여러 개에서 주문하면 수량을 합쳐 재고와 비교한다.
- 재고가 부족하면 주문 전체를 저장하지 않고 재고도 바꾸지 않는다.
- 성공하면 상태를 `주문 접수`로 저장하고 `201`과 저장된 주문을 반환한다. 주문 내용은 6.3.4의 조회 결과와 같은 모양이다.

요청 예:

```json
{
  "items": [
    { "menuId": 1, "quantity": 2, "optionIds": [1, 2] },
    { "menuId": 3, "quantity": 1, "optionIds": [5] }
  ]
}
```

위 예시는 아메리카노(ICE) 재고를 2, 말차라떼(ICE) 재고를 1 줄인다. 아메리카노(ICE) 한 잔의 항목 금액은 `(2500 + 500 + 500) × 2 = 7000`이다.

#### 6.3.3 주문 정보 조회

주문 ID를 전달하면 해당 주문 정보를 보여 준다.

- 메서드와 경로: `GET /api/orders/:orderId`
- 응답: `200`
- 본문은 `id`, `orderedAt`, `status`, `totalPrice`, `items`다.
- `items`의 항목은 `menuId`, `menuName`, `quantity`, `options`, `linePrice`다.
- `options`의 항목은 `name`, `price`다.
- 주문이 없으면 `404`다.

#### 6.3.4 관리자 화면용 API

6.2의 관리자 흐름에 필요하다.

메뉴 재고 목록

- `GET /api/admin/menus`
- 응답은 6.3.1의 메뉴 필드에 `stock`을 더한 목록이다.

재고 수정

- `PATCH /api/admin/menus/:menuId/stock`
- 본문은 `{ "delta": 1 }` 또는 `{ "delta": -1 }`이다.
- 결과는 0 미만으로 내리지 않는다. 재고가 0일 때 `-1`을 보내도 재고는 0이다.
- 응답 `200`은 `{ "id": 1, "stock": 9 }`다.

주문 목록

- `GET /api/orders`
- `orderedAt`이 최근인 주문이 앞에 온다.
- 각 항목의 모양은 6.3.3과 같다.

주문 상태 변경

- `PATCH /api/orders/:orderId/status`
- 본문은 없다. 서버가 현재 상태의 다음 상태로 바꾼다.
- `주문 접수`는 `제조 중`, `제조 중`은 `완료`가 된다.
- `완료`에서 다시 요청하면 `409`이고 상태는 유지된다.
- 응답 `200`은 변경된 주문이며 모양은 6.3.3과 같다.

### 6.4 이 백엔드에서 하지 않는 것

- 사용자 인증, 결제
- 메뉴 추가와 삭제, 이름과 가격과 설명 수정
- 옵션 추가와 삭제, 옵션 가격 수정
- 주문 삭제, `완료` 이후의 상태
- 장바구니 저장. 장바구니는 주문이 저장되기 전까지 브라우저에만 있다.
