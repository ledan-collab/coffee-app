#커피 주문 앱

## 1. 프로젝트 개요

### 1.1 프로젝트명
커피 주문 앱

### 1.2 프로젝트 목적
사용자가 커피 메뉴를 주문하고, 관리자가 주문을 관리할 수 있는 간단한 풀스택 웹 앱

### 1.3 개발 범위
- 주문하기 화면(메뉴 선택 및 장바구니 기능)
- 관리자 화면(재고 관리 및 주문 상태 관리)
- 데이터를 생성/조회/수정/삭제할 수 있는 기능

##2. 기술 스택
- 프런트엔드: HTML, CSS, 리액트, 자바스크립트
- 백엔드: Node.js, Express
- 데이터베이스: PostgreSQL

## 3. 기본 사항
- 프런트엔드와 백엔드를 따로 개발
- 기본적인 웹 기술만 사용
- 사용자 인증이나 결제 기능은 제외
- 메뉴는 커피 메뉴만 있음

## 4. 주문하기 화면

### 4.1 화면 목적
사용자가 커피 메뉴를 확인하고 장바구니에 담은 뒤 주문한다. 앱을 열면 이 화면이 먼저 보인다.

### 4.2 화면 구성
화면은 위에서 아래로 세 영역으로 나뉜다. 각 영역은 사각형 테두리로 구분한다.

1. 헤더
2. 메뉴 목록
3. 장바구니

### 4.3 헤더
- 왼쪽에는 앱 이름 `COFFE-APP`을 표시한다.
- 오른쪽에는 `관리자`를 표시한다. 선택하면 관리자 화면으로 이동한다.

### 4.4 메뉴 목록
메뉴를 가로로 나열한다. 메뉴 하나는 카드 하나이며, 카드 안 내용은 위에서 아래로 다음 순서다.

1. 사진 영역. 이미지가 없으면 `사진`이라고 표시한다.
2. 메뉴 이름. 온도는 이름 뒤 괄호로 붙인다.
3. 가격. 천 단위 쉼표와 `원`을 붙인다.
4. 간단 설명.

와이어프레임의 예시 메뉴는 다음과 같다.

| 메뉴 이름 | 가격 | 설명 |
| --- | --- | --- |
| 아메리카노(ICE) | 2,500원 | 간단설명 |
| 아메리카노(HOT) | 2,500원 | 간단설명 |
| 말차라떼(ICE) | 4,500원 | 간단설명 |

동작은 다음과 같다.

- 메뉴 카드를 선택하면 그 메뉴 1개가 장바구니에 담긴다.
- 이미 담긴 메뉴를 다시 선택하면 수량이 1 증가한다.
- 카드 안에 별도의 담기 버튼은 없다.
- 이 화면에서는 재고 수량을 보여 주지 않는다.

### 4.5 장바구니
장바구니는 메뉴 목록 아래에 둔다.

- 왼쪽 위에는 `장바구니`를 표시한다.
- 오른쪽 위에는 `총 금액 {금액}원`을 표시한다. 금액은 담긴 항목의 합계다.
- 목록의 한 줄은 `{메뉴 이름} X {수량}`과 그 줄의 금액이다. 줄 금액은 단가에 수량을 곱한 값이다.
- 같은 메뉴는 한 줄로 합친다.
- 오른쪽 아래에는 `주문하기` 버튼을 둔다.

와이어프레임의 예시는 다음과 같다.

- 아메리카노(ICE) X 1, 2,500원
- 말차라떼(ICE) X 1, 4,500원
- 총 금액 7,000원

동작은 다음과 같다.

- 장바구니가 비어 있으면 목록은 비어 있고 총 금액은 `0원`이다. 이때 `주문하기`는 주문을 만들지 않는다.
- `주문하기`를 선택하면 장바구니에 담긴 메뉴와 수량으로 주문을 만들고, 장바구니를 비운다.
- 주문 완료를 알리는 별도 화면은 없다. 주문 뒤에는 빈 장바구니가 있는 주문하기 화면을 유지한다.

### 4.6 표시 규칙
- 금액은 `2,500원`처럼 천 단위 쉼표와 `원`으로 표시한다.
- 수량은 `X 1`처럼 `X`와 숫자로 표시한다.
- 온도는 메뉴 이름의 일부로 표시한다. HOT와 ICE는 서로 다른 메뉴다.

### 4.7 이 화면에서 하지 않는 것
- 샷, 사이즈 같은 옵션 선택
- 장바구니 수량 감소와 항목 삭제
- 로그인, 결제
- 재고 수량 표시와 재고 수정. 재고와 주문 상태 관리는 관리자 화면의 범위다.

## 5. 관리자 화면

### 5.1 화면 목적
관리자가 주문 건수를 확인하고, 메뉴 재고를 조정하고, 주문의 제조 상태를 바꾼다. 주문하기 화면의 `관리자`를 선택하면 이 화면으로 이동한다.

### 5.2 화면 구성
화면은 위에서 아래로 네 영역으로 나뉜다. 각 영역은 사각형 테두리로 구분한다.

1. 헤더
2. 대시보드
3. 재고
4. 주문현황

### 5.3 헤더
- 왼쪽에는 앱 이름 `COFFEE-APP`을 표시한다.
- 오른쪽에는 `주문하기`를 표시한다. 선택하면 주문하기 화면으로 이동한다.

### 5.4 대시보드
영역 왼쪽 위에 `대시보드`를 표시한다. 그 아래에는 칸 네 개를 가로로 둔다. 각 칸은 이름과 건수를 보여 준다.

| 칸 | 의미 | 표시 예 |
| --- | --- | --- |
| 총 주문 | 모든 주문 수 | 0건 |
| 주문 접수 | 주문 접수 상태인 주문 수 | 0건 |
| 제조 중 | 제조 중 상태인 주문 수 | 0건 |
| 제조 완료 | 제조 완료 상태인 주문 수 | 0건 |

건수는 `0건`처럼 숫자 뒤에 `건`을 붙인다. 주문이 없거나 상태가 바뀌면 네 칸의 숫자가 바로 갱신된다. 총 주문은 주문 접수, 제조 중, 제조 완료의 합과 같다.

### 5.5 재고
영역 왼쪽 위에 `재고`를 표시한다. 메뉴 하나를 카드 하나로 가로로 나열한다. 카드 안 내용은 위에서 아래로 다음 순서다.

1. 메뉴 이름. 주문하기 화면과 같은 이름을 쓴다.
2. 재고 수량. `10개`처럼 숫자 뒤에 `개`를 붙인다.
3. `+` 버튼과 `-` 버튼.

와이어프레임의 예시 재고는 다음과 같다.

| 메뉴 이름 | 재고 |
| --- | --- |
| 아메리카노(ICE) | 10개 |
| 아메리카노(HOT) | 10개 |
| 말차라떼(ICE) | 10개 |

동작은 다음과 같다.

- `+`를 누르면 해당 메뉴 재고가 1 증가한다.
- `-`를 누르면 해당 메뉴 재고가 1 감소한다.
- 재고는 0개보다 작아지지 않는다. 0개일 때 `-`를 눌러도 수량은 0개로 유지된다.
- 재고는 이 버튼으로만 바뀐다. 주문이 들어와도 재고는 줄지 않는다.

### 5.6 주문현황
영역 왼쪽 위에 `주문현황`을 표시한다. 주문 하나는 한 줄이다. 한 줄은 왼쪽부터 주문 시각, 주문 메뉴, 금액, 상태 버튼 순이다.

- 주문 시각은 `11월 18일 15:02`처럼 `M월 D일 HH:mm`로 표시한다.
- 주문 메뉴는 `{메뉴 이름} X {수량}`이다. 한 주문에 메뉴가 여러 개면 같은 줄에 함께 보여 준다.
- 금액은 그 주문의 총액이다. 천 단위 쉼표와 `원`을 붙인다.
- 오른쪽 끝의 상태 버튼에는 현재 상태를 표시한다.

와이어프레임의 예시는 다음과 같다.

- 11월 18일 15:02, 아메리카노(ICE) X 1, 2,500원, 버튼 `접수 주문`

동작은 다음과 같다.

- 주문하기 화면에서 주문이 만들어지면 주문현황 맨 위에 한 줄이 추가된다. 처음 상태는 주문 접수이고, 버튼 문구는 `접수 주문`이다.
- 최근 주문이 위에 온다.
- 주문이 없으면 목록은 비어 있다.
- 상태 버튼을 누르면 주문이 다음 상태로 바뀌고, 버튼 문구와 대시보드 건수도 함께 바뀐다.

상태 순서는 다음과 같다.

1. 주문 접수. 버튼 문구는 `접수 주문`이다.
2. 제조 중. 버튼 문구는 `제조 중`이다.
3. 제조 완료. 버튼 문구는 `제조 완료`이다.

`제조 완료` 버튼을 눌러도 상태는 바뀌지 않는다. 완료된 주문은 목록에 그대로 남는다.

### 5.7 표시 규칙
- 대시보드 건수는 `0건`처럼 숫자와 `건`으로 표시한다.
- 재고는 `10개`처럼 숫자와 `개`로 표시한다.
- 금액과 수량은 주문하기 화면과 같다. 금액은 `2,500원`, 수량은 `X 1`이다.
- 메뉴 이름은 주문하기 화면과 같다. HOT와 ICE는 서로 다른 메뉴다.

### 5.8 이 화면에서 하지 않는 것
- 메뉴 추가, 메뉴 삭제, 가격과 설명 수정
- 주문 삭제
- 로그인, 결제
- 제조 완료 이후의 상태
